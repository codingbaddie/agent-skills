# 產出後複查（憑證據，不憑記憶）

給 `SKILL.md` Step 9 與模式 B 共用。**這份檢查表由 Claude 執行，不是丟給需求方自己勾。**

## 為什麼一定要憑證據

最容易失效的檢查長這樣：

> ❌「現況流程有拆到動作層級嗎？」
> ❌「例外情況有二次複查嗎？」

這是在問**自己的行為**——「我有沒有問過？」。答案永遠是「有」，因為整段訪談還在對話脈絡裡，模型會覺得自己問過了。**context 在不在都一樣，因為題目問錯方向。**

有效的檢查長這樣：

> ✅「第 1 節裡出現的每一個動詞，後面有沒有跟著『用什麼工具、看什麼欄位、輸入什麼』？把沒有的列出來。」
> ✅「第 4 節的例外表有幾列？逐一對照第 3 節的每個角色，哪些角色沒有專屬例外？」

這種題目**就算整段訪談都在 context 裡也騙不了**——文件裡沒有那段文字，就是沒有。

**規則：每一條檢查都要能指向文件裡的具體位置（有／沒有），不能是「我覺得問夠了」。**

---

## A. 第 1 節 現況與痛點

| 檢查動作 | 不通過的樣子 | 怎麼補 |
|---|---|---|
| 把第 1 節出現的**每個動詞**列出來，看後面有沒有跟著具體動作 | 有「處理」「跟進」「關心」「發送提醒」「確認」，但沒說用什麼系統、打開哪個畫面、看哪些欄位、輸入什麼、發到哪個渠道 | 回頭補問那個步驟的實際操作 |
| 把第 1 節出現的**每個工具／系統名稱**列成清單 | 有縮寫或代號沒有全名（例：「用 MA 發」「POS」） | 補問全名與用途 |
| 把第 1 節出現的**每個數字**列成清單，逐一找它的出處 | 有數字但文件裡沒寫怎麼算出來的、資料期間是什麼 | 補問分子分母與期間；若對方是估的，**標記為估計值**（見 F 區） |
| 搜尋「待確認」「不清楚」「不太知道」 | 有一整段別人的工作流程被一句話帶過 | 標記待確認＋負責人＋預計確認時間，不要留空 |
| 逐一對照每個痛點，看旁邊有沒有「理想上希望怎樣」 | 痛點寫完就換下一段 | 補問期望 |
| 搜尋「有人在做」「不是他的職責」這類描述 | 有寫出來 ✅ 這是好的 | 但要確認有追問：現在誰正式負責？做完之後誰拿數據去要求改善？ |

## B. 第 2 節 需求方與商業目標

| 檢查動作 | 不通過的樣子 | 怎麼補 |
|---|---|---|
| 數 Goal Cascade 表有幾列 | 只有提出人一個人 | 追問還有誰對結果負責、或會被影響 |
| 逐一看每個 Goal Metric 有沒有「÷」或明確的分子分母 | 寫「提升」「優化」「變好」「更有效率」 | 逼到有公式與目標值 |
| 把公式裡的**每個名詞**挑出來，各問一次「有沒有第二種讀法」 | 「當月到期會員」「首購人數」「這批人」 | 逼到只剩一種讀法（自然月還是合約週期？cohort 還是當期？涵蓋哪些範圍？） |
| **上層目標若是絕對數、下層指標是比率，找中間的基數** | 上層「每月 200 人」、下層「30%」，但文件裡沒有分母大約幾人 | Goal Cascade 在數學上斷掉了，補問分母與這條路徑佔上層目標的比重 |
| 逐一看每個指標，問「這個數字今天實際拿得到嗎」 | 依賴的歸因／追蹤機制文件裡沒交代 | 記成指標的前提缺口 |
| 找出所有「無」「未設定」的 Goal Metric | 該角色是這次要依賴他執行的人 | 追問一次為什麼不用正式指定 |
| 找出描述**不在場的人**的目標／流程的段落 | 沒有標記「（由 OO 代答）」 | 補標記 |

## C. 一致性（讀完全文才做得了，最容易被略過）

| 檢查動作 | 不通過的樣子 | 怎麼補 |
|---|---|---|
| **把全文的數字列成一張清單**，找出同一件事出現兩次的 | 一處寫「3-5 人工時」、另一處寫「5-7 小時」 | 把兩處並排問哪個才對、單位是不是同一種 |
| **每組百分比自己加一次** | 加不到 100% | 缺的那幾 % 是什麼狀態？**沒交代的部分常常才是關鍵** |
| **每個推算式自己算一次** | 算出來跟文件寫的不一樣 | 直接指出；算對也要問每個參數的來源 |
| 找出**數值剛好相同但語境不同**的數字 | 「3,000 位訂閱客戶」與「每年 3,000 位首購」 | 問是巧合還是同一個數字被用在兩個地方 |
| **把每個 Goal Metric 跟它對應的業務規則並排**，比對動詞 | 指標算「**完成**回診」、規則觸發「未**預約**回診」 | 預約 ≠ 完成，驗收會爭議，問以哪個為準 |
| 逐一看每個指標，找有沒有規則會產生對應行為 | 有指標但沒有任何規則指向它 | 這個指標靠什麼達成？ |
| 逐一看每條規則，找有沒有指標能反映它的成效 | 有規則但對不到任何指標 | 做完之後怎麼知道有沒有用？ |
| **把第 2、3、4 節的角色名單各列一次，三份對照** | 有角色出現在第 3 或 4 節，卻不在第 2 節 | 他是單純受益者，還是這次要依賴他執行的？後者要追問為什麼沒有目標 |
| 找出**同一群人或同一個東西的不同稱呼** | 「M3 續訂率」與「3 期實際扣款率」其實是同一個目標；「門市顧問」在不同段落指不同的人 | 統一寫法，或明確註明兩者是同一件事 |

## D. 第 4 節 業務規則與例外

| 檢查動作 | 不通過的樣子 | 怎麼補 |
|---|---|---|
| 搜尋技術字眼：「排程」「掃描」「AI」「關鍵字」「API」「取代 XX script」 | 業務規則寫成了實作方式 | 退回去問「業務上要達成的結果是什麼」，順便問可接受的誤判率 |
| 逐一看每條規則，找**沒有主詞**的句子 | 「發出警示通知」「會被提醒」「資料會更新」 | 誰做？哪個渠道？內容包含什麼？ |
| 找出把「人工 XX」當成角色寫的地方 | 「人工標記」「人工排查」——這不是角色 | 誰有權標記／回查？多久一次？全查還抽查？ |
| **逐一看每條規則，分開問「誰偵測到條件成立」與「誰執行後續動作」** | 只寫一個「負責角色」，看不出是哪一個 | 分開寫。**如果「誰偵測」是人，那件事本身通常就是這份需求要消滅的痛點**（人工判定、人工比對、人工回查），要確認它有沒有被寫進痛點與範圍——不要讓讀者以為是要維持人工偵測 |
| 找出所有標記／燈號類的規則，看有沒有失效或解除規則 | 標了之後永遠有效，沒說誰能取消 | 補問時效與更正機制 |
| **數例外表有幾列** | 少於 2 條，或只有 happy path | 用類別提示補問：時間／人員／數量／資料／狀態邊界 |
| **逐一對照第 3 節的每個角色**，看例外表有沒有涵蓋 | 有角色完全沒有專屬例外 | 各問一次「這個角色在這個情境有沒有不尋常的狀況」 |
| 搜尋「原則上不會」「應該不會」「通常不會」 | 用來打發請假、離職、資料缺漏 | 追問真的發生時怎麼處理、會不會汙染指標 |
| 找例外表裡有沒有「過去事故」類的條目 | 完全沒有 | 這是最有說服力的一類，補問有沒有出過包、被客訴、內部吵過架 |
| 找出把人工作業保留下來的例外 | 有，但沒說頻率與耗時 | 效益宣稱要扣掉這部分，補問多久發生一次、每次多久 |

## E. 第 5 節 範圍界定

| 檢查動作 | 不通過的樣子 | 怎麼補 |
|---|---|---|
| 看有沒有「理想樣貌」段落且不是空的 | 直接跳到 In Scope | 補問不考慮開發成本的完整版 |
| 逐一看每個排除項的理由 | 理由是「先做一個比較快」「這樣應該比較好做」 | **需求方自我設限**——分期是 PM 的工作，拉回去問理想樣貌 |
| **逐一對照每個痛點，在 In Scope 裡找對應項** | 某個痛點找不到對應 | 明確寫出「這次做完這個痛點是完全沒被處理」，避免上線後預期落差 |
| 對每個新加的項目做一次測試：拿掉它，原本的痛點情境還完整成立嗎 | 成立，而且卡關的是另一群人／另一個場景 | 那是順便夾帶，建議另開一份 BRD |
| Out of Scope 也要搜尋技術字眼 | 寫成技術方案 | 改寫成業務結果 |

## F. 數字來源與待確認

| 檢查動作 | 不通過的樣子 | 怎麼補 |
|---|---|---|
| **逐一對照全文每個數字，看有沒有標來源等級** | 沒標——PM 分不出哪些能信 | 每個數字標成三種之一：**〔實測〕**（有查過，附出處）／**〔估計〕**（憑印象或推算）／**〔待查〕**（現在不知道，之後補）。詳見 `elicitation-radar.md` 的「數字來源追問」 |
| 數待確認表有幾列，跟全文出現的「待確認」字樣對照 | 有待確認散落在各節沒收進表 | 統一整理 |
| 逐一看待確認表每一列的後兩欄 | 缺「預計確認時間」或「由誰確認」 | 沒有時間點的待確認，PM 排不進決策時程 |
| 看期望完成時間有沒有理由 | 沒寫，或寫「越快越好」 | 補問有什麼硬約束（稽核／合約／編制檢視／季度目標） |
| 看「如果延後」有沒有量化 | 只寫「會有影響」 | 延後一季具體損失多少 |
| 看佐證資料的時點 | 距今很久 | 問有沒有更新的資料、結論會不會因此改變 |

## G. 讀者測試

| 檢查動作 | 不通過的樣子 |
|---|---|
| **把全文的縮寫與內部代稱列成一張清單**，逐一確認文件裡有解釋 | 有沒解釋的（憑印象打勾一定會漏，一定要實際列清單） |
| **只讀第 1、2 節**，假裝自己完全沒參與過訪談，判斷「這件事要不要做、多急」 | 判斷不出來 → 背景與目標寫得不夠 |

---

## 複查結果怎麼呈現

不要只說「檢查過了」。**列出實際找到的每一條**，格式：

> **第 X 節**：〔症狀〕→ 需要補問〔什麼〕

全部通過才說通過。找到的項目要**當場回頭補問需求方**，不要自己腦補填上，也不要標成「待確認」草草了事——「待確認」只保留給當事人當下真的不知道的客觀事實。
